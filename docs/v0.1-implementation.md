# v0.1 vertical slice (prototype)

This is a **dry-run-only** prototype. It **does not** contact, modify, or configure external systems and makes no claim to protect production workloads.

## Run

Requires .NET SDK 8.

```sh
dotnet run --project src/Gorgoneion.Cli -- evaluate --policy examples/policy.example.json --input examples/eve.example.jsonl
dotnet run --project tests/Gorgoneion.SmokeTests
```

Reads Suricata-style newline-delimited EVE JSON and a locally maintained allowlist of **destination** IP addresses. Proposed actions use only the hardcoded `firewall.mock` adapter and are never executed.

## Assumptions / limitations

- The prototype maps alert severity 1..4 to a configurable upper threshold (lower number = higher priority in Suricata conventions).
- The authorized target registry is an explicit local policy file, **not** proof that the operator owns the endpoint. External enforcement must add strong asset attestation and identity/approval.
- Source IPs do not establish attacker identity. This is a simulated defensive recommendation only.
- No remote APIs, sockets, FW rule changes or OS privileges are used.
- No real persistent evidence store, digital signatures, streaming backpressure, anomaly correlation, CIDR ranges or strategy registry yet.
- Invalid lines produce denied outputs. CLI returns a nonzero exit status for invalid policy/file errors.

## Development priorities

1. Audit existing OSS workflow and policy engines before creating custom equivalents.
2. Split CLI into library and adapter interfaces only when real integration demands it.
3. Add schema, large-input limits, streaming and structured diagnostic controls before production deployments.
4. Add formal testing and SBOM after the license decision.

## Security baseline

The sample addresses are RFC 5737 documentation-only networks. Never substitute a production address without explicit authorization and appropriate controls.
