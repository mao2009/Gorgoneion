# v0.1 architecture acceptance & evidence matrix

This document reviews the **dry-run prototype boundary**, not Gorgoneion as a deployable security solution.

| Requirement | Evidence | Verdict |
| --- | --- | --- |
| Agentless-first and central controller boundary | [architecture.md](architecture.md), [integration-contracts.md](integration-contracts.md) | Documented |
| Existing OSS preferred to new IDS/firewall/SOAR | [OSS candidates](oss-candidates.md), [SOAR review](soar-reuse-review.md) | Documented; distribution audit remains open (#3) |
| Normalized EVE event + bounded input | `EveParser`, `EveIngestor`, `schemas/eve-subset.schema.json`, synthetic fixtures | Prototype implemented; schema describes subset only |

| No external write or hack-back | `firewall.mock` and preview capability descriptors; CI in-memory HTTP test doubles | CI demonstrates the tested paths have no live actions |
| No approval ⇒ no proposed action | `AuthorizationGateTests`, `PipelineTests`, mandatory `--authorization` CLI input | Tested |
| Traceability and tamper evidence | `AuditTrail`, `AuditTrailTests`, `verify-audit` | Prototype hash chain, not cryptographic authenticity |
| Repeatable acceptance | `Gorgoneion.sln`, `.github/workflows/ci.yml`, smoke suite and sample CLI | GitHub Actions required green prior to merge |

## Explicit non-goals

- No production hardening, real attack mitigation, command execution, live firewall change, or intrusive counterattack.
- No guaranteed visibility into encrypted or endpoint-only activity without suitable sensors/integrations.
- No agent installation required on clients; independently deployed OSS may need sensors or agents.
- No real equipment tests yet (#13).
- No legally final license or commercial distribution clearance (#2 and #3).
- No secret storage or verifiable actual ownership enrollment (#5).
- No remotely anchored/immutable log, guaranteed tamper attribution or robust failure recovery (#8).

## Acceptance process

A successful CI build and smoke run, synthetic event CLI run, audit verification, and review of the documented safety boundaries together satisfy **Issue #1's architecture-and-acceptance-design scope**. They do not establish production readiness or finish the implementation work in separate Issues #2–#8 and #13.
